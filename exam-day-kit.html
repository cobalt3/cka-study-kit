Minute 0 · set up your shell first

The two-minute investment that saves twenty

Before you touch a single task, paste this. Every keystroke you save on kubectl compounds across 20 questions.

bash Aliases & completion

alias k=kubectl
source <(kubectl completion bash)
complete -o default -F __start_kubectl k

# fast dry-run + explain shortcuts
export do="--dry-run=client -o yaml"
export now="--force --grace-period=0"

# now you can write:
k run nginx --image=nginx $do > pod.yaml
k delete pod nginx $now

The $do and $now exports are the two most-cited speed hacks in the CKA community.

vim ~/.vimrc for clean YAML

cat <<'EOF' > ~/.vimrc
set number
set expandtab
set tabstop=2
set shiftwidth=2
EOF

YAML is whitespace-sensitive and tabs break it. This makes every paste indent correctly — one of the quietest point-savers on the exam.

Every question · the first thing you type

Read the task's context before solving it

Each question runs on a possibly-different cluster. Getting this wrong means solving the right task on the wrong cluster — an automatic zero. It is the number-one avoidable mistake.

1st Switch context — always

# the exam gives you this line per question — RUN IT
kubectl config use-context <ctx>

# sanity check where you are
k config current-context
k get nodes

ssh Some tasks live on a node

# node-level tasks (kubelet, etcd, kubeadm)
ssh cp        # the exam sets up ssh for you
sudo -i       # become root before editing /etc
exit          # RETURN to the student node when done!

Forgetting to exit back and running the next question as root on the wrong host is a classic trap.

RBAC self-grade

k create role r --verb=get,list --resource=pods
k create rolebinding b --role=r \
  --serviceaccount=dev:sa
k auth can-i list pods \
  --as=system:serviceaccount:dev:sa

  --delete-emptydir-data

etcd (read paths from the manifest)

sudo ETCDCTL_API=3 etcdctl \
  snapshot save /tmp/etcd.db \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=...ca.crt --cert=...server.crt \

Clock management · how to not run out of time

The rules that decide pass or fail

Triage the questions themselves

Each task shows its weight (2–13%). Do the cheap, high-weight ones first. If a task isn't done in ~8 minutes, flag it and move on — a 4% task is never worth sinking 15 minutes into while three others go untouched.

Partial credit is real

Scoring is per-task and often per-step. Get the pod running even if you can't perfect the probe. Never leave a task blank because it's not flawless — bank what you can.

Verify, then leave it

Always confirm your change worked (Running, endpoints populated, curl responds) — but once it's verified, stop polishing and move on. Over-checking a done task is stolen time.

Two attempts, use them

Registration includes a free retake and two killer.sh sessions. Treat attempt one as low-stakes if nerves hit — but you won't need it if killer.sh already felt clearable.

★
The single highest-leverage habit: run kubectl config use-context at the start of every question, and verify your fix worked before leaving. These two habits alone eliminate the most common ways strong candidates still fail.
