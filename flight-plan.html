The map · where the points are

Five domains, weighted very unevenly

Study time should follow the weights, not your comfort. Troubleshooting alone is nearly a third of the exam and it draws on every other domain — treat it as the destination, not a topic.

Troubleshooting

30%

Cluster & node failures, failing workloads, broken networking, reading logs and events. Highest-value domain — drill it last, after the others give you the vocabulary.

Cluster Architecture, Installation & Configuration

25%

kubeadm install & upgrade, RBAC, etcd backup/restore, managing node lifecycle. Helm & Kustomize for installing components.

Services & Networking

20%

Pod & service connectivity, NetworkPolicies, the Gateway API, Ingress, and CoreDNS.

Workloads & Scheduling

15%

Deployments & rollouts, ConfigMaps & Secrets, scaling, scheduling, resource limits, self-healing.

Storage

10%

StorageClasses, dynamic provisioning, PVs & PVCs, volume types, access modes & reclaim policy.

The cargo · what to actually learn

Core skills by domain

Every item here is something you should be able to do at a terminal without looking it up. If you can only describe it, you haven't learned it yet.

Troubleshooting 30%

  • Read kubectl describe & events to root-cause a stuck pod
  • Debug a NotReady node: kubelet, containerd, certs, disk
  • Inspect control-plane static pods in /etc/kubernetes/manifests
  • journalctl -u kubelet, crictl ps/logs
  • Fix DNS/service resolution failures end to end

Cluster & Config 25%

  • kubeadm init / join / upgrade a cluster
  • etcd snapshot save & restore
  • RBAC: Roles, ClusterRoles & bindings, ServiceAccounts
  • drain / cordon / uncordon nodes
  • Install with Helm & render with Kustomize

Services & Networking 20%

  • ClusterIP / NodePort / LoadBalancer, plus port-forward
  • Write NetworkPolicies (ingress + egress)
  • Ingress rules and the newer Gateway API
  • Debug CoreDNS & in-cluster name resolution

Workloads & Scheduling 15%

  • Deployments, rollouts, rollout undo, scaling
  • ConfigMaps & Secrets into env / volumes
  • Requests/limits, nodeSelector, affinity, taints & tolerations
  • Probes: liveness, readiness, startup

Storage 10%

  • PV / PVC binding and access modes
  • StorageClasses & dynamic provisioning
  • Reclaim policies (Retain vs Delete)
  • Mount volumes into pods

Exam-day speed meta

  • alias k=kubectl + kubectl completion
  • k run/k create --dry-run=client -o yaml to scaffold
  • --context per question — always check it first
  • Bookmark-free doc navigation on kubernetes.io
  • Flag & skip: never sink 10 min into one 4% task

The itinerary · a 6-week run

Study schedule

Assumes ~8–10 focused hours per week and that you can already use a Linux shell. Compress to 4 weeks if you work with Kubernetes daily; stretch to 8 if it's new.

1

Foundations & your lab

Stand up the Multipass cluster below. Learn the architecture (API server, scheduler, controller-manager, etcd, kubelet, kube-proxy). Live in kubectl: get, describe, explain, dry-run generation.

2

Workloads & scheduling

Deployments, ReplicaSets, rollouts, ConfigMaps/Secrets, probes, resources, affinity, taints/tolerations. Rebuild everything from --dry-run YAML, not the docs.

3

Services, networking & storage

Service types, Ingress + Gateway API, NetworkPolicies, CoreDNS. Then PV/PVC, StorageClasses, dynamic provisioning. Break connectivity on purpose and fix it.

4

Cluster administration

The scary ones: kubeadm upgrade a minor version, etcd snapshot & restore, RBAC from scratch, node drain/upgrade. Do each at least three times until it's automatic.

5

Troubleshooting drills

Deliberately break your lab — wrong kubelet config, bad manifest, expired-looking cert, dead CoreDNS — and recover. This is 30% of the exam; spend real time here.

6

Timed practice & polish

Full timed mock exams (killer.sh comes with your exam registration — use both attempts). Fix weak spots, sharpen aliases and speed, book the real thing.

★
The single best resource: killercoda.com has free CKA scenario environments, and killer.sh (two sessions included when you register) is deliberately harder than the real exam — if you clear it, exam day feels calm.

The vessel · build your lab

A 3-node cluster on Ubuntu Multipass

Multipass spins up real Ubuntu VMs in seconds. We'll build one control-plane and two workers with kubeadm — the same tool the exam tests — so practice mirrors the real thing. Works on macOS, Windows, or Linux.

01

Install Multipass

Install for your host, then confirm it runs.

# macOS
brew install --cask multipass
# Windows: download the installer from multipass.run
# Linux
sudo snap install multipass

multipass version
02

Launch three VMs

Give the control plane at least 2 CPUs and 2 GB RAM (a kubeadm requirement). Adjust down for workers if your machine is tight.

multipass launch 22.04 --name cp     --cpus 2 --memory 2G --disk 10G
multipass launch 22.04 --name node1  --cpus 2 --memory 2G --disk 10G
multipass launch 22.04 --name node2  --cpus 2 --memory 2G --disk 10G

multipass list   # note each VM's IP
03

Prepare every node (run on all three)

Open a shell with multipass shell cp (repeat for node1, node2) and run this block on each. It disables swap, loads kernel modules, sets sysctls, and installs containerd.

# --- swap off (kubeadm refuses to run with swap on) ---
sudo swapoff -a
sudo sed -i '/ swap / s/^/#/' /etc/fstab

# --- kernel modules + sysctl for the container network ---
cat <<EOF | sudo tee /etc/modules-load.d/k8s.conf
overlay
br_netfilter
EOF
sudo modprobe overlay && sudo modprobe br_netfilter

cat <<EOF | sudo tee /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF
sudo sysctl --system

# --- containerd runtime ---
sudo apt-get update && sudo apt-get install -y containerd
sudo mkdir -p /etc/containerd
containerd config default | sudo tee /etc/containerd/config.toml >/dev/null
# use the systemd cgroup driver (kubelet expects this)
sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml
sudo systemctl restart containerd && sudo systemctl enable containerd
04

Install kubeadm, kubelet & kubectl (all three)

Pin to the current stable minor series. Holding the packages stops an accidental apt upgrade from breaking the cluster.

sudo apt-get install -y apt-transport-https ca-certificates curl gpg
curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.34/deb/Release.key \
  | sudo gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
echo "deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] \
https://pkgs.k8s.io/core:/stable:/v1.34/deb/ /" \
  | sudo tee /etc/apt/sources.list.d/kubernetes.list

sudo apt-get update
sudo apt-get install -y kubelet kubeadm kubectl
sudo apt-mark hold kubelet kubeadm kubectl
i
Install one minor version behind the exam's (exam is v1.35, so v1.34 here) on purpose — then you can practice the upgrade task, which is worth real points.
05

Initialise the control plane (on cp only)

Use the cp VM's IP from step 2 as the API advertise address. The pod CIDR here matches Calico's default.

sudo kubeadm init \
  --apiserver-advertise-address=<CP_IP> \
  --pod-network-cidr=192.168.0.0/16

# set up kubectl for the ubuntu user
mkdir -p $HOME/.kube
sudo cp /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config

kubectl get nodes   # cp shows NotReady until the CNI is installed

Copy the kubeadm join … command it prints — you'll need it in step 7.

06

Install a pod network (on cp)

Calico brings the cluster to Ready and lets you practice NetworkPolicies later.

kubectl apply -f https://raw.githubusercontent.com/projectcalico/calico/v3.28.0/manifests/calico.yaml

kubectl get pods -n kube-system -w   # wait for Running, then Ctrl-C
07

Join the workers (on node1 and node2)

Paste the join command from step 5. Lost it? Regenerate on cp with kubeadm token create --print-join-command.

sudo kubeadm join <CP_IP>:6443 --token <token> \
  --discovery-token-ca-cert-hash sha256:<hash>
08

Confirm the cluster (on cp)

All three nodes should report Ready within a minute or two.

kubectl get nodes -o wide

# smoke test
kubectl create deployment web --image=nginx --replicas=3
kubectl expose deployment web --port=80 --type=NodePort
kubectl get pods -o wide   # pods spread across node1 / node2
✓
Save your snapshots. Once it's healthy, multipass stop cp node1 node2 then multipass snapshot each VM. When a troubleshooting drill wrecks the cluster, restore in seconds instead of rebuilding. multipass start/stop pauses the lab between sessions to save battery.
